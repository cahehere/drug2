제작 전에 확정할 사항

  • 지난 날짜 기록 수정: 기본안은 수정 가능하게 하되, 선택한 날짜의 기록만 수정합니다.
  • 날짜 변경: 새 날짜는 미체크로 시작하고, 이전 기록은 최근 7일 표에 남깁니다.
  • 표시 기간: 최근 7일만 보여주며, 오래된 기록 검색은 이번 범위에서 제외합니다.

4. 테스트 체크리스트 10개

정상 사용 5개

  • 약 이름과 아침을 선택하면 아침 목록에 표시된다.
  • 아침·점심·저녁에 등록한 약이 각각 맞는 시간대에 표시된다.
  • 약을 체크하면 체크 표시와 오늘 복용률이 바뀐다.
  • 최근 7일 표에 날짜별 복용 개수가 표시된다.
  • 삭제 확인 후 해당 약만 사라지고, 취소하면 남아 있다.

잘못된 입력 또는 예외 5개

  • 약 이름을 빈칸으로 등록하려 하면 저장되지 않는다.
  • 약 이름에 공백만 입력하면 저장되지 않는다.
  • 음수 복용 개수나 복용률이 저장·표시되지 않는다.
  • 지원하지 않는 파일 형식을 선택해도 가져오기가 실행되지 않는다는 안내가 나온다.
  • 날짜가 바뀌어도 기록이 다른 날짜와 섞이지 않는다.

5. 이번에는 만들지 않을 것

  • 알림음, 푸시·문자·이메일 알림
  • 실명, 병원명, 처방번호 등 개인정보 입력
  • 의학적 조언, 복용량 추천, 약 상호작용 판단
  • 약 사진 촬영이나 약 이름 자동 인식
  • 로그인, 여러 사람 공유, 서버 저장, 인터넷 동기화
  • 파일 가져오기·내보내기
  • 월별·연간 통계와 그래프
  • 앱 설치 파일이나 별도 서버

제작 요청 요약

  1. 파일 하나짜리 HTML 웹앱으로 만든다.
  2. 초보자가 이해할 수 있는 쉬운 말과 큰 안내를 사용한다.
  3. 글자는 18px 이상, 버튼은 크게, 색 대비는 뚜렷하게 만든다.
  4. 약 이름과 아침·점심·저녁 시간대를 등록한다.
  5. 오늘 먹을 약을 시간대별로 보여준다.
  6. 약마다 복용 여부를 체크하게 한다.
  7. 오늘 복용률을 계산한다.
  8. 최근 7일 기록을 날짜별 표로 보여준다.
  9. 약 삭제 전 확인을 받는다.
  10. 데이터는 인터넷 없이 현재 기기에만 저장한다.
  11. 개인정보를 입력받지 않는다.
  12. 기록용 앱이며 의학적 조언을 하지 않는다는 안내를 넣는다.
  13. 날짜별 기록을 섞지 않는다.
  14. 날짜 기능을 만들기 전에 날짜 처리 방법을 먼저 설명한다.
  15. 빈칸, 음수, 잘못된 파일 형식 등 예외 상황을 점검한다.
